# 创作工具与生产流程

## Purpose

提供网文创作的工具链与生产流程设计，帮助作者高效利用AI辅助工具，建立可持续的写作工作流，实现从构思到发布的全流程优化。

## When to Use

- 用户需要选择AI写作工具
- 用户需要设计提示词模板
- 用户需要规划写作工作流
- 用户需要选择码字/管理工具
- 用户需要制定发布与运营策略

## Instructions

### AI辅助写作工具对比

#### DeepSeek
- 优势：中文理解力强、长文本处理好、性价比高
- 适用：大纲生成、章节初稿、角色对话
- 提示词：需要详细的人设和剧情指令

#### ChatGPT
- 优势：创意丰富、逻辑清晰、多语言
- 适用：创意发散、剧情推演、世界观构建
- 提示词：英文提示词效果更佳

#### Claude
- 优势：长文本处理优秀、风格模仿能力强
- 适用：长篇续写、风格迁移、深度润色
- 提示词：需要提供风格样本

#### 豆包/Kimi
- 优势：中文语境理解好、免费额度多
- 适用：日常写作辅助、快速生成
- 提示词：简洁直接即可

### 提示词模板

#### 大纲生成提示词
```
你是一位专业的网文编辑。请根据以下信息生成一份详细的小说大纲：

题材：[题材类型]
核心设定：[金手指/核心设定]
主角人设：[性格标签+背景]
目标平台：[平台名称]
预计字数：[总字数]
目标情绪：[爽/虐/甜/燃/悬疑/治愈]
核心反转：[读者以为A，实际是B]
开篇承诺：[前三章必须兑现的冲突或爽点]

要求：
1. 包含完整的起承转合
2. 每卷有明确的核心冲突
3. 标注爽点分布位置
4. 标注断章钩子位置
5. 字数分配合理
6. 输出“一句话卖点、前三章细纲、核心反转埋点、情绪曲线、风险点”五个部分
```

#### 番茄短篇大纲提示词
```
请按番茄短篇节奏生成8000到20000字大纲。

输入：
题材：[都市重生/婚恋虐渣/悬疑反转/其他]
目标情绪：[读者读完最强烈的情绪]
核心反转：[全文最大反转]
女主/男主人设：[欲望+缺陷+关系压力]
对手压迫：[谁让主角憋屈，怎么压]
结尾余味：[爽完、虐完或反转后的最后一口气]

输出：
1. 一句话卖点
2. 300字黄金开篇
3. 分段大纲：开场、铺垫、升级、反转、收尾
4. 每段字数占比和情绪变化
5. 伏笔回收表
6. 容易AI味或拖沓的风险点
```

#### 章节生成提示词
```
你是一位网文写手。请根据以下信息撰写第[N]章：

前情提要：[前一章概要]
本章目标：[本章要完成的剧情目标]
出场角色：[角色名+当前状态]
爽点设计：[本章爽点类型+结构]
断章钩子：[本章结尾钩子类型]
文风要求：[文风类型]
字数要求：[字数范围]

要求：
1. 开头承接上一章
2. 节奏紧凑，不注水
3. 爽点结构完整
4. 结尾设置钩子
5. 角色行为符合人设
```

#### 角色对话提示词
```
你是一位网文写手。请为以下场景撰写对话：

角色A：[名字]+[性格标签]+[当前情绪]+[说话风格]
角色B：[名字]+[性格标签]+[当前情绪]+[说话风格]
场景：[场景描述]
对话目的：[对话要推动什么剧情]
潜台词：[表面之下真正在说什么]

要求：
1. 每个角色有独特的说话方式
2. 对话自然，不生硬
3. 包含潜台词
4. 推动剧情发展
5. 适当使用语气词
```

### 写作工作流设计

#### 标准工作流

1. **构思阶段**（1-2天）
   - 确定题材与核心设定
   - 生成大纲框架
   - 设计主要角色

2. **大纲阶段**（3-5天）
   - 细化大纲至章节级
   - 标注爽点与钩子位置
   - 建立设定文档

3. **开篇阶段**（1周）
   - 精写黄金三章
   - 反复打磨开篇
   - 内投签约

4. **连载阶段**（持续）
   - 日更2-3章
   - AI辅助+人工改写
   - 保持存稿3-5天

5. **运营阶段**（持续）
   - 关注数据反馈
   - 与读者互动
   - 调整写作策略

#### 2小时日更4000字模板

适用于时间紧、需要AI辅助但不能直接发布AI初稿的作者。

| 时间 | 动作 | 交付物 | 重试触发 |
|---|---|---|---|
| 0-10分钟 | 复读上一章结尾、今日细纲、人物状态 | 本章目标1句 + 3个必写剧情点 | 写不出目标句，回到大纲阶段重定本章功能 |
| 10-25分钟 | 用AI生成章节骨架，不要正文铺满 | 6到8个场景节拍，每节拍标爽点或钩子 | 场景节拍无冲突，追加“谁阻止主角、代价是什么” |
| 25-65分钟 | 分段生成初稿，每次只生成800到1200字 | 初稿3000到4500字 | 对话像说明书，补角色语气和潜台词后重跑该段 |
| 65-100分钟 | 人工改写最高风险段落 | 人工改写版正文 | 连续两段句式相同，改句长和动作密度 |
| 100-115分钟 | 检查断章、爽点兑现、设定一致性 | 修订清单 | 结尾没有继续阅读理由，重设危机或信息揭露 |
| 115-120分钟 | 记录今日问题和明日钩子 | 50字复盘 + 明日章目标 | 复盘为空，至少记录一个要修的角色或节奏问题 |

最小闭环：今天必须留下“本章目标、正文、修订清单、明日钩子”四个文件或条目。少一个就不算完成日更流程。

### 码字与管理工具

- **码字精灵**：专注码字，番茄钟+字数统计
- **墨者写作**：多端同步，云端存储
- **橙瓜码字**：网文专用，数据统计
- **石墨文档**：协作写作，多端同步
- **Notion/Obsidian**：设定管理，知识库

### 发布与数据分析

#### 关键数据指标
- 追读率：读者持续阅读的比例
- 完读率：读完单章的比例
- 收藏率：阅读后收藏的比例
- 推荐票/月票：读者认可度
- 评论活跃度：读者参与度

#### 数据优化策略
- 追读率低→优化开篇和断章
- 完读率低→减少注水，加快节奏
- 收藏率低→增强钩子和期待感
- 评论少→增加互动话题点

## Execution Protocol

1. 先确认用户处于构思、大纲、正文、润色、发布还是数据复盘阶段。
2. 推荐工具前先问约束：预算、平台、是否需要长文本、是否多人协作、是否本地存储。
3. 给提示词时必须包含输入字段、输出格式、质量标准和失败重试方式。
4. 给工作流时按“今天能执行”的粒度拆分，不只给宏观流程。

### Artifact Handoff

任何工作流都要明确产物交接，避免“用了很多工具但没有可发布文本”。

| 阶段 | 必须产物 | 交给下一阶段前检查 |
|---|---|---|
| 构思 | 一句话卖点、目标平台、主角欲望 | 是否能支撑前三章冲突 |
| 大纲 | 章级目标、爽点、断章钩子 | 是否每章都有局势变化 |
| 正文 | 可读初稿、问题标记 | 是否保留人设和设定一致性 |
| 润色 | 最终稿、删改记录 | 是否去掉AI腔和注水段 |
| 发布 | 简介、标签、更新时间 | 是否匹配平台读者期待 |
| 复盘 | 数据、问题判断、下次动作 | 是否有观察周期和止损条件 |

推荐工具时必须说明它服务哪一个产物；如果说不清产物，就不要推荐该工具。

### Failure Handling

| 触发条件 | 处理动作 |
|---|---|
| 用户目标不明确 | 先让用户选择阶段，不直接推荐工具清单 |
| 工具信息可能过期 | 标注需复核价格、额度和功能限制 |
| 提示词输出跑偏 | 增加角色约束、样例输出和禁止项后重写 |
| 工作流执行成本过高 | 压缩到每日最小闭环：构思、产出、复查、记录 |

### CHECKPOINT

最终输出前确认：方案能当天执行、提示词有明确输入输出、每一步有交付物、工具服务具体产物、重试触发清楚、没有推荐与用户预算冲突的工具。

### Anti-Patterns

- 不要把工具清单当成解决方案。
- 不要给没有输入字段的空泛提示词。
- 不要让作者依赖单一AI生成完整正文后直接发布。
- 不要忽略备份、版本管理和设定文档同步。
